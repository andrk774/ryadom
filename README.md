# Рядом

Сервис частных объявлений на Node.js и SQLite. Версия 0.3.

## Запуск

Нужен Node.js 22.13 или новее.

```powershell
npm.cmd ci
npm.cmd start
```

Откройте http://127.0.0.1:3000. На пустой базе в локальном режиме создаются демонстрационные объявления и аккаунты. Вход: `anna@example.com` / `demo12345`.

При первом открытии старой базы сервер создаёт согласованную резервную копию `data/ryadom.db.before-v1.bak`, затем добавляет новые таблицы и поля. Аккаунты, объявления, переписка и фото сохраняются. Старые объявления считаются одобренными. Перед обновлением остановите предыдущую версию сервера и запустите новую.

## Возможности

1. **Аккаунт:** подтверждение email, восстановление пароля по одноразовой ссылке. Сброс пароля завершает все сеансы. Смена пароля из профиля сохраняет текущий сеанс и завершает остальные.
2. **Модерация:** жалобы на объявления и пользователей, очередь публикаций, одобрение и отклонение с причиной, блокировка пользователей, журнал действий. Новые и изменённые объявления по умолчанию проходят проверку. Снятые модератором объявления недоступны посторонним в поиске, избранном и по прямой ссылке.
3. **Сохранённые поиски:** до 30 на аккаунт. После публикации подходящего объявления появляется уведомление **на сайте**, включая фильтры характеристик. Повторное одобрение одного объявления не дублирует уведомление. Email-рассылка по поискам не включена.
4. **Характеристики и фильтры:** транспорт — марка, год, пробег; недвижимость — площадь, комнаты, продажа/аренда; одежда — размер и бренд; электроника — бренд и модель. Поля необязательны для совместимости со старыми объявлениями и разными подкатегориями.
5. **Фото:** проверка изображения, отклонение повреждённых файлов, уменьшение до 1920×1920 и преобразование в WebP, автоматическая ориентация, поворот, выбор главного фото, изменение порядка и удаление из объявления. До 10 фото по 10 МБ, до 40 мегапикселей. Публикация во время загрузки заблокирована.
6. **Чат:** полная история с подгрузкой по 50 сообщений, до 3 фото в сообщении, отметки прочтения видимых сообщений. Вложения доступны отправителю и участникам соответствующего диалога. Чат обновляется раз в 4 секунды при видимой вкладке.
7. **Профиль:** аватар, описание, город и имя, смена email с подтверждением нового адреса и проверкой текущего пароля, смена пароля. Публичные профили не содержат email.
8. **Черновики:** автосохранение на сервер через 800 мс после изменения, список черновиков, восстановление после перезагрузки, ручное сохранение, предпросмотр. После публикации черновик удаляется. Снятое или проданное объявление можно опубликовать снова из «Мои объявления».

Сохранены избранное, отзывы после переписки, просмотры, поиск с нормализацией кириллицы, категории, города и сортировка.

## Назначить модератора

Сначала зарегистрируйте нужный аккаунт. Из папки проекта:

```powershell
npm.cmd run admin -- your-email@example.com
```

Обновите страницу: в меню появится «Модерация». Роль назначается только локальным инструментом. При нестандартном `DATA_DIR` задайте его и для этой команды. Модераторы не могут заблокировать себя или другого модератора.

## Почта

Без SMTP в локальном режиме письма сохраняются в `data/mail/*.json`. Внутри — получатель, тема и ссылка, которую можно открыть в браузере. Папка не доступна через HTTP. Реальная отправка в этом режиме не происходит.

Для отправки задайте `SMTP_URL`, `MAIL_FROM` и внешний адрес `APP_URL`. Пример — в `.env.example`. Приложение читает переменные процесса; `.env` можно загрузить командой `node --env-file=.env server/index.js`.

Ссылка восстановления действует 1 час, подтверждения email — 24 часа. Новая ссылка той же цели заменяет предыдущую. Смена email вступает в силу после подтверждения и завершает сеансы. В базе хранятся хеши токенов.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `PORT` | `3000` | Порт |
| `HOST` | `127.0.0.1` | Адрес сервера |
| `DATA_DIR` | `./data` относительно проекта | База, фото, локальные письма |
| `APP_URL` | `http://127.0.0.1:PORT` | Ссылки в письмах; в production обязательна HTTPS-ссылка |
| `SMTP_URL` | нет | Например `smtps://user:password@smtp.example.com:465` |
| `MAIL_FROM` | нет | Адрес отправителя |
| `NODE_ENV` | development | `production` отключает создание демо-данных и требует SMTP, MAIL_FROM и HTTPS APP_URL |
| `MODERATION_REQUIRED` | включено | `0` отключает предварительную проверку новых публикаций |
| `COOKIE_SECURE` | нет | `1` — cookie только по HTTPS; в production включено всегда |
| `TRUST_PROXY` | нет | `1` — IP из последнего адреса X-Forwarded-For, только за своим прокси |

Для публичного сервера используйте отдельный DATA_DIR без демо-аккаунтов с общедоступным паролем, HTTPS и резервное копирование. Первый модератор назначается оператором после регистрации.

## Проверки

```powershell
npm.cmd test
npx.cmd playwright install chromium
npm.cmd run test:browser
```

Тесты используют временные базы и не меняют рабочие данные. Проверяются права доступа, миграция, токены, модерация, фильтры, уведомления, изображения, черновики и история чата. Браузерный тест сам запускает временный сервер, проверяет основные сценарии и мобильный интерфейс, сохраняет скриншоты в `.qa/`. Существующий Chromium можно указать через `PLAYWRIGHT_EXECUTABLE`. Реальная SMTP-доставка требует почтового сервера и не проверяется этими тестами.

## Новое в версии 0.3

- **Антиспам:** лимиты регистрации, входа, жалоб и сообщений сохраняются в SQLite и переживают перезапуск. После нескольких попыток запрашивается Cloudflare Turnstile; токен проверяется на сервере, одноразовый, с проверкой домена и действия. Без ключей локальный режим ограничивает попытки ответом 429. В production оба ключа обязательны. Настройте домен виджета равным домену APP_URL. [Документация проверки Turnstile](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).
- **Блокировка собеседников:** кнопки в чате и профиле, отдельный список в настройках. Отправка запрещена обоим участникам, история остаётся доступной.
- **Уведомления о сообщениях:** внутри сайта и письма по выбору пользователя после подтверждения email. Письма ждут минуту, объединяются по диалогу в десятиминутные интервалы, не отправляются для прочитанных или заблокированных диалогов. Неудачные отправки повторяются до пяти попыток. Push-уведомления не используются.
- **Районы и расстояние:** район в объявлении и фильтрах, координаты места встречи с округлением до 0,01°, поиск в радиусе 1–500 км. Координаты можно указать вручную или получить с разрешения браузера. Объявления без координат не участвуют в поиске по радиусу. Карта и внешний геокодер не требуются.
- **Срок публикации:** по умолчанию 30 дней, напоминание за три дня, продление из «Мои объявления». Истёкшие публикации исчезают из поиска сразу и архивируются фоновым обслуживанием. Повторная публикация проходит модерацию. LISTING_DAYS меняет срок новых публикаций (1–365).
- **Статистика:** просмотры, текущие добавления в избранное, число начатых диалогов, дневная статистика за 30 дней. Повторные просмотры одного пользователя или анонимного IP в течение суток не увеличивают счётчик. Старые накопленные просмотры сохраняются, дневная статистика собирается после обновления.

## Резервные копии, восстановление и очистка

Пока сервер работает, обслуживание запускается раз в минуту. Резервная копия делается при первом запуске и затем раз в сутки; сохраняются семь последних завершённых копий. Копия содержит согласованный снимок SQLite и все фото, используемые объявлениями, профилями, черновиками и чатами. Контрольные суммы, целостность SQLite и внешние ключи проверяются автоматически.

BACKUP_DIR задаёт каталог копий, по умолчанию `data/backups`. Для защиты от потери диска задайте отдельный диск или хранилище. Рабочие данные и копии исключены из Git.

```powershell
npm.cmd run backup
npm.cmd run backup:verify -- "C:/ryadom-backups/backup-..."
npm.cmd run restore -- "C:/ryadom-backups/backup-..." "C:/ryadom-restored"
npm.cmd run cleanup
```

Восстановление разрешено только в пустую папку и проверяет полученную копию. Остановите сервер, проверьте восстановленные данные и переключите DATA_DIR на новый каталог. Тесты автоматически проверяют восстановление базы вместе с фото. Миграция создаёт дополнительный снимок `ryadom.db.before-v1.bak` или `ryadom.db.before-v2.bak` в зависимости от старой версии.

Очистка удаляет только фото без ссылок из объявлений, профилей, черновиков и сообщений, не ранее чем через 24 часа после загрузки. Фото удалённого объявления сохраняются, если оно используется в переписке.

## Почта и мониторинг

SMTP_URL и MAIL_FROM настраиваются через окружение (пример в `.env.example`); реальные пароли не коммитьте. SMTP-адаптер проверяется тестом с локальным SMTP-сервером. Доставка внешним получателям требует ваших настроек почтового провайдера. Без SMTP письма остаются в `data/mail`.

`GET /api/health` проверяет доступность базы и подходит для внешнего мониторинга. В «Модерация → Состояние сервиса» доступны статус копий, очередь писем и последние ошибки. Ошибки запросов записываются в базу и stderr с ID; тела запросов, cookies и query-параметры не записываются. Ошибки хранятся 30 дней. Интерфейс обновляет состояние при открытии страницы; внешние SMS/Telegram-оповещения не подключены.

GitHub Actions запускает API-тесты и браузерную проверку при push и pull request. Данные пользователей, письма, `.env`, копии и node_modules в репозиторий не входят.
